# 项目目录

## 根目录原则

根目录只保留用户直接需要的入口、打包脚本、说明和运行数据库。应用代码集中在 `mcu_studio/`，工具链、文档、打包配置和生成物分别归档，避免为了拆分而拆分。

```text
McuStdio/
├─ main.py
├─ build.py
├─ live_watch_history.db
├─ Readme.md
├─ .gitignore
├─ mcu_studio/
│  ├─ __init__.py
│  ├─ core.py
│  ├─ workers.py
│  └─ ui.py
├─ assets/
│  ├─ mcu_studio.ico
│  └─ screenshots/main-window.png
├─ data/
├─ doc/
├─ dist/
├─ packaging/
├─ runtime/
├─ tools/
└─ artifacts/
```

## 各目录职责

- `main.py`：唯一的源码运行入口，PyInstaller 也从这里启动。
- `build.py`：唯一打包入口；修改顶部 `APP_NAME` 可设置 EXE 名称，该脚本本身不会被打入应用。
- `live_watch_history.db`：本机配置、变量和布局数据。源码运行时与 `main.py` 同级，打包后与 EXE 同级；它不是程序资源目录。
- `mcu_studio/core.py`：配置、数据库、ELF/DWARF、路径和 OpenOCD 参数等核心逻辑。
- `mcu_studio/workers.py`：J-Link/OpenOCD 后台采样、读取、写入和连接任务。
- `mcu_studio/ui.py`：启动配置页、三个调试窗口、悬浮窗口、变量浏览器和波形交互。
- `assets/`：应用图标和 README 使用的界面截图。
- `runtime/`：OpenOCD、ARM GCC、cfg 和 SVD；不被 Git 忽略，应跟随开源仓库提交。
- `packaging/`：当前唯一发布 spec；历史配置只保存在 `doc/archive/packaging/`。
- `tools/validate_project.py`：不连接硬件的全项目静态与模拟校验入口。
- `dist/`：最终 EXE 输出目录，默认 `dist/Mcu_Studio.exe`，被 Git 忽略。
- `artifacts/`：PyInstaller 中间文件和其他可重新生成产物。

## 运行数据位置

程序使用入口文件或可执行文件所在目录作为数据根目录：

```text
源码运行：McuStdio/live_watch_history.db
打包运行：dist/live_watch_history.db
```

首次运行没有数据库时会自动创建。发布干净版本时只需分发 EXE；需要迁移已有监视列表和配置时，再同时复制数据库。

## 打包输出

执行 `python .\build.py` 后：

```text
dist/
├─ Mcu_Studio.exe
└─ live_watch_history.db   # 首次运行生成，或由用户自行携带
```

不要直接调用历史 spec，也不要把 PyQt6 与 PySide6/PyQt5 同时收集到成品中。
