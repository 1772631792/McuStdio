# 已知问题

## 1. OpenOCD target 脚本不完整

界面预置了 `py32f0xx.cfg`，但当前附带的 OpenOCD 脚本库中没有该文件。N32/PY32 等芯片也不能直接假定与 STM32 target 完全兼容。

影响：选择缺失或不匹配的 target cfg 时，OpenOCD 会启动失败或连接错误的芯片配置。

建议：提供芯片厂商对应的 target cfg，并在进入工作站前验证文件存在。

## 2. OpenOCD 启动错误不可见

当前启动 OpenOCD 后只固定等待一小段时间，没有检查子进程是否退出，也没有把 stderr 显示给用户。

影响：cfg 错误、探针不存在或端口占用时，界面通常只显示“链路断开”。

## 3. 固定端口可能连到错误实例

当前使用 GDB 3333、Telnet 4444 和 TCL 6666。如果已有另一个 OpenOCD 占用端口，新进程可能启动失败，而界面继续连到旧的 6666 服务。

影响：有连错目标板并读写错误内存的风险。

## 4. OpenOCD 高速多通道读取边界

当通道间距较大或存在 8 字节变量时，多条 `mdb/mdh/mdw` 会被拼成一个 TCL 请求，当前解析假设每条命令都返回独立行。

影响：可能丢失某些返回值，或把数值分配给错误通道。

## 5. packed 非对齐变量可能读错

块读取对一个变量只从其起始所在的 32 位 word 取值。当 `uint16_t` 或 `uint32_t` 从 word 末尾开始并跨越下一个 word 时，高位字节会丢失。

## 6. OpenOCD 不能绝对保证不复位

OpenOCD 启动时会执行 target 初始化。是否触发复位取决于 target cfg、调试器、运输方式和接线。

建议：在电机、功率电源等高风险设备上使用前，先在低风险板卡上验证。

## 7. Qt 打包冲突

开发环境中如果同时安装 PyQt6、PySide6 或 PyQt5，pyqtgraph/PyInstaller 钩子可能尝试收集多套 Qt，导致打包失败、DLL 冲突或 EXE 启动异常。

当前防护：

- 仅保留 `packaging/Mcu_Studio.spec` 作为发布入口。
- 设置 `PYQTGRAPH_QT_LIB=PyQt6` 和 `QT_API=pyqt6`。
- 在 Analysis 中排除 PySide6/shiboken6、PyQt5、PySide2/shiboken2。
- 排除 pyqtgraph 可选导入的 matplotlib 和 scipy。

打包时只使用：

```powershell
python .\build.py
```

`build.py` 会在打包后检查 EXE 归档，发现第二套 Qt 时直接报错。不要使用 `doc/archive/packaging/` 中的历史 spec。
