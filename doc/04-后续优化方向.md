# 后续优化方向

## 原则

MCU Live Watch Studio 的核心价值是：不依赖断点和串口协议，尽量不改变 MCU 实时行为，直接观察 ELF 中的变量。后续优化应保持界面简洁，优先提高可信度和稳定性，而不是扩展成完整 IDE。

## P0：优先完善

### 实际采样状态

在底部状态栏增加紧凑指标，例如“实际 2.8 kHz / 失败 0 / 重连 0”。这能让用户判断 8 kHz 设置是否真正达到目标，也能快速发现 USB 或探针不稳定，不需要新增复杂页面。

### 本地滚动诊断日志

把目前少数静默忽略的异常写入有大小上限的本地日志，例如保留最近 1–2 MiB。正常使用不弹日志窗口；只有连接失败或用户主动查看时展示摘要。

### 硬件实测矩阵

为常见组合记录连接、读取、写入、重连和连续运行结果：

- J-Link + 当前实际目标板。
- ST-Link + STM32F1/F4/H7。
- DAPLink/CMSIS-DAP + 一个 Cortex-M 目标。
- OpenOCD 自定义厂商 cfg。

建议加入 8 小时和 24 小时持续采样测试，观察内存、GUI 响应、错误次数和实际采样率。

### 默认只读保护

可以增加一个默认开启的“锁定写入”开关。锁定时允许读取和波形，但禁用变量写入、复位和烧录；需要操作硬件时再主动解锁。它不会增加日常读取步骤，却能降低误双击或误操作风险。

## P1：有价值但保持克制

### 触发捕获

允许对一个变量设置简单条件，例如“大于阈值”或“发生变化”，保存触发前后有限时间的三通道数据。它比无限历史记录更适合定位偶发异常，也不会把软件变成复杂示波器。

### 数据导出增强

当前已经可以选择已绑定变量，将缓存快照导出为 CSV。后续可增加时间范围选择，并附带变量类型、ELF 身份、后端和目标采样率等元数据；仍保持明确的一次性导出，不在后台长期生成大文件。

### ELF 身份确认

数据库除路径外可保存 ELF 文件大小、修改时间或 Build ID。固件重新编译后自动刷新地址；发现数据库来自不同固件时给出清晰提示，进一步避免旧地址误读。

### 重连统计

保留最近一次断线原因、重连次数和后端状态变化时间。自动重连仍保持安静，只在持续失败时提示用户。

## P2：按实际需求决定

- 允许用户维护少量常用厂商 cfg 收藏，而不是内置所有芯片数据库。
- 增加监视配置的导入/导出，方便同一工程在多台电脑之间迁移。
- 增加变量备注或短别名，但不改变 ELF 原始符号名。
- 对超大数组提供分页展开，避免一次生成数千个树节点。

## 不建议加入

- 断点、单步、调用栈、反汇编和完整寄存器调试。
- 将串口助手、RS-485、逻辑分析仪全部塞进同一个程序。
- 任意数量的动态调试窗口和复杂停靠布局。
- 为追求功能数量而加入长期无人维护的协议插件。

这些功能会模糊定位、增加误操作和维护成本。串口或 RS-485 工具更适合保持为独立的小程序，共享视觉风格即可。
