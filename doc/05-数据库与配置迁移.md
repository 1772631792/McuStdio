# 数据库与配置迁移

程序使用单个 SQLite 文件 `live_watch_history.db` 保存工作状态。它比每次重写整份 JSON 更适合频繁添加变量、保存窗口和更新单项配置。

## 数据库位置

数据库位置取决于运行方式：

```text
源码运行：项目根目录/live_watch_history.db
单文件版：优先使用 EXE 同级已有 DB，否则使用 %LOCALAPPDATA%/McuStudio/live_watch_history.db
目录版：Mcu_Studio/data/live_watch_history.db
```

首次启动时如果文件不存在，程序会自动创建数据目录和数据库。目录版通过 EXE 同级的 `portable-mode.flag` 识别；整个目录仍应放在当前用户可写的位置。

## 保存内容

- ELF 路径和当前后端。
- J-Link 安装目录和器件名。
- OpenOCD 程序、interface cfg、target cfg 和日志选项。
- 深色/浅色主题。
- 三个调试窗口中的变量、结构体成员和数组成员。
- 每个 CH 绑定的波形变量、曲线颜色和单图/双图/三图布局。
- 主调试区与波形区的分割比例、多个波形的高度比例、窗口尺寸和采样频率。
- ELF 浏览器变量的最近使用权重；“全部文件”视图会优先显示最近使用的变量。
- 最近使用的输入类型等界面状态。
- 多变量滑动调节的范围、步进、自动扩展和实时写入选项。
- 受控容量的波形历史：每个变量最高约 200 Hz，总量自动保留最近约 100 万行。
- 兼容旧功能保留的 C 代码缓存。

## 多套项目配置

启动页顶部提供一条紧凑配置栏：

```text
项目配置：[主配置 ▼]  [+]  [×]  [清空配置]
```

- `主配置` 固定存在，不能删除；旧版单配置数据库升级后，原有内容自动归入主配置。
- `+` 新建一套空配置并立即切换过去。
- `×` 删除当前非主配置及其变量、波形和历史数据；选中主配置时按钮禁用。
- `清空配置` 保留当前名称，删除该配置在数据库中的 UI 状态、工程设置、变量、滑动条、波形绑定、布局和历史采样。被清除的历史不再参与 CSV 导出；已经导出到磁盘的 CSV 文件不会被删除。
- 下拉切换配置时，会分别恢复 ELF、调试后端、变量、滑动条、波形、布局和采样历史。

所有配置仍保存在同一个 `live_watch_history.db` 中，不需要再复制或替换数据库文件。

重新打开软件时会使用当前 ELF 校验保存的变量路径，再恢复调试窗口、滑动条和波形绑定。运行期间重新编译只标记新 ELF 待烧录，不会让仍在运行的旧固件提前使用新地址；烧录成功后才按最终 ELF 更新同名变量地址并删除已经不存在的名字。高速原始波形保存在当前进程内；SQLite 后台保存限频后的长期历史，CSV 导出时会将数据库历史与内存中的最新数据合并。

采样历史使用独立写入线程和 SQLite 回滚日志模式。正常运行只持久保留 `live_watch_history.db`；事务提交期间可能极短暂出现 `live_watch_history.db-journal`，提交完成后会自动删除。旧版留下 `-wal` 与 `-shm` 时，先退出旧版，再用新版打开一次主 DB，让 SQLite 完成恢复和日志模式切换。

## 备份与迁移配置

日常切换直接使用启动页的项目配置下拉框，不需要复制 DB。复制数据库主要用于整库备份或迁移：

1. 先关闭软件，确保 SQLite 连接已经释放。
2. 复制 `live_watch_history.db`。
3. 按板卡或项目命名，例如：

```text
configs/
├─ motor-foc-jlink.db
├─ power-f4-stlink.db
└─ sensor-daplink.db
```

4. 需要恢复时，把备份文件复制回数据目录并命名为 `live_watch_history.db`。
5. 再启动软件，从项目配置下拉框选择目标配置，并检查 ELF 和探针路径是否仍然有效。

不要在软件运行中覆盖数据库。SQLite 连接仍打开时替换文件可能造成当前进程继续使用旧句柄，甚至留下难以理解的状态。

## 迁移到另一台电脑

1. 复制完整目录版和对应数据库，或在新电脑首次运行后关闭软件再覆盖 DB。单文件版可把数据库与 EXE 一起复制，程序会优先读取同级 DB。
2. 重新确认 ELF、SEGGER 和 OpenOCD 的绝对路径。
3. 如果目录结构不同，在启动页重新浏览选择文件。
4. 进入工作站后检查变量地址是否来自当前 ELF。

数据库中包含本机绝对路径，分享给其他人前应确认是否包含用户名、工程目录等不希望公开的信息。

## 同一变量出现在多个窗口

数据库用“变量路径 + 窗口编号”区分记录，因此同一变量可以存在于多个调试窗口。可见窗口刷新时会合并相同读取请求，波形绑定也是全局共享；从一个窗口删除变量时，只要其他窗口仍保留该变量，就不会误解除波形通道。

## 恢复干净状态

如果配置已经不需要：

1. 关闭软件。
2. 先备份原 DB。
3. 把 `live_watch_history.db` 改名，例如 `live_watch_history.old.db`。
4. 重新启动，程序会创建空数据库。

确认新配置正常后再决定是否删除旧文件。不要用文本编辑器修改 SQLite 文件；确实需要检查内容时使用 SQLite 数据库工具，并先做备份。

## 为什么不直接使用 JSON

- SQLite 修改单个变量时不必重写整个文件。
- 事务和唯一键能减少半写入、重复记录和互相覆盖。
- 结构体展开后可能包含大量成员，批量写入数据库更稳定。
- 波形历史可以后台批量提交，并通过行数上限控制磁盘占用。
- 对当前使用方式而言，一个 DB 文件同样容易复制和归档。

如果未来需要人类可读的交换格式，适合增加“导入/导出 JSON”，但运行时仍以 SQLite 为主。
