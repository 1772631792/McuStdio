# 数据库与配置迁移

程序使用单个 SQLite 文件 `live_watch_history.db` 保存工作状态。它比每次重写整份 JSON 更适合频繁添加变量、保存窗口和更新单项配置。

## 数据库位置

数据库始终位于程序入口旁边：

```text
源码运行：项目根目录/live_watch_history.db
打包运行：Mcu_Studio.exe 同级/live_watch_history.db
```

首次启动时如果文件不存在，程序会自动创建。EXE 所在目录必须允许当前用户写入；不要把便携版直接放在普通用户无写权限的系统目录。

## 保存内容

- ELF 路径和当前后端。
- J-Link 安装目录、器件名和可选 SVD 路径。
- OpenOCD 程序、interface cfg、target cfg 和日志选项。
- 深色/浅色主题。
- 三个调试窗口中的变量、结构体成员和数组成员。
- 每个 CH 绑定的波形变量、曲线颜色和单图/双图/三图布局。
- 主调试区与波形区的分割比例、多个波形的高度比例、窗口尺寸和采样频率。
- ELF 浏览器变量的最近使用权重；“全部文件”视图会优先显示最近使用的变量。
- 最近使用的输入类型等界面状态。
- 兼容旧功能保留的 C 代码缓存。

重新打开软件时会使用当前 ELF 校验保存的变量路径，再恢复调试窗口和波形绑定。已经改名或删除的变量不会从旧地址恢复。数据库不保存 MCU 实时采样历史；波形缓存只存在于当前进程内，需长期保留时导出 CSV。

## 备份与切换配置

最简单的配置管理方式就是复制 DB：

1. 先关闭软件，确保 SQLite 连接已经释放。
2. 复制 `live_watch_history.db`。
3. 按板卡或项目命名，例如：

```text
configs/
├─ motor-foc-jlink.db
├─ power-f4-stlink.db
└─ sensor-daplink.db
```

4. 要切换配置时，把目标文件复制回程序目录并命名为 `live_watch_history.db`。
5. 再启动软件，检查 ELF 和探针路径是否仍然有效。

不要在软件运行中覆盖数据库。SQLite 连接仍打开时替换文件可能造成当前进程继续使用旧句柄，甚至留下难以理解的状态。

## 迁移到另一台电脑

1. 复制 EXE 和对应数据库，或在新电脑首次运行后关闭软件再覆盖 DB。
2. 重新确认 ELF、SEGGER 和 OpenOCD 的绝对路径。
3. 如果目录结构不同，在启动页重新浏览选择文件。
4. 进入工作站后检查变量地址是否来自当前 ELF。

数据库中包含本机绝对路径，分享给其他人前应确认是否包含用户名、工程目录等不希望公开的信息。

## 同一变量出现在多个窗口

数据库用“变量路径 + 窗口编号”区分记录，因此同一变量可以存在于多个调试窗口。可见窗口刷新时会合并相同读取请求，波形绑定也是全局共享；从一个窗口删除变量时，只要其他窗口仍保留该变量，就不会误解除波形通道。

## 恢复干净状态

如果配置已经不需要：

1. 关闭软件。
2. 先备份原 DB。
3. 把 `live_watch_history.db` 改名，例如 `live_watch_history.old.db`。
4. 重新启动，程序会创建空数据库。

确认新配置正常后再决定是否删除旧文件。不要用文本编辑器修改 SQLite 文件；确实需要检查内容时使用 SQLite 数据库工具，并先做备份。

## 为什么不直接使用 JSON

- SQLite 修改单个变量时不必重写整个文件。
- 事务和唯一键能减少半写入、重复记录和互相覆盖。
- 结构体展开后可能包含大量成员，批量写入数据库更稳定。
- 对当前使用方式而言，一个 DB 文件同样容易复制和归档。

如果未来需要人类可读的交换格式，适合增加“导入/导出 JSON”，但运行时仍以 SQLite 为主。
